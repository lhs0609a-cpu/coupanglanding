# 네이버 카탈로그 수동등록 운영 실측

## 범위와 결과

- 웹 운영 배포: `dpl_997o2yFTttW6WeVA6hFs4c2jMcvc`, `https://www.megaload.co.kr`.
- 카탈로그 데이터는 실제 운영 DB에서 읽었다. 사용자 계정이나 쿠팡 상품을 변경하지 않았다.
- 최초 표본 3개 대표이미지 요청은 모두 HTTP 400이었다. 운영 프록시에 `/naver-image`가 없어서 기존 쿠팡 API 자격증명 검사로 들어가는 문제였다.
- Fly.io 운영 코드를 내려받아 저장소 코드와 비교했다. 차이는 네이버 이미지 전달 기능과 이를 위한 바이너리 읽기 함수였다.
- 이미지 기능을 `coupang-api-proxy`에 반영했다. 운영 머신 버전 22, 이미지 `deployment-01M2F79JW7F2BNWD2XH1NPWTEW`를 확인했다.
- Fly 배포 마지막 smoke-check 단계는 관리 API 인증 오류로 실패를 보고했다. 이후 별도 상태 조회에서 새 이미지와 실행 상태를 확인했고 실제 HTTP 요청으로 검증했다.

## 동일 상품 재측정

측정 위치는 작업 PC이며, 아래 시간은 PC → 운영 Fly 프록시 → 네이버 CDN → PC의 전체 수신 시간이다. 브라우저 화면 전환 시간이나 Vercel 이미지 변환 시간은 포함하지 않는다.

| 상품번호 | 이미지 | 수정 후 HTTP | 시간 | 수신 바이트 |
|---|---|---:|---:|---:|
| 13412372396 | 대표 | 200 | 962 ms | 811,793 |
| 13412372396 | 상세 | 200 | 593 ms | 4,158,932 |
| 13236893104 | 대표 | 200 | 1,223 ms | 4,308,437 |
| 13236893104 | 상세 | 200 | 154 ms | 129,796 |
| 13076380761 | 대표 | 200 | 364 ms | 431,181 |
| 13076380761 | 상세 | 200 | 184 ms | 540,866 |

6장 모두 JPEG 시그니처를 확인했다. 별도 표본 3장도 HTTP 200으로 수신했고 Sharp 디코딩으로 PNG/JPEG 형식과 1000×1000 해상도를 확인했다.

## 미검증 항목

- 지정 사용자 계정으로 카탈로그 선택 → 배송·마진 설정 → 기존 검수 화면 진입.
- 운영 Vercel 이미지 API의 인증 후 응답 및 브라우저 이미지 업로드.
- 등록 전 최종 검증과 실제 쿠팡 상품 게시.

해당 단계는 사용할 계정 이메일을 요청한 상태다. 임의의 기존 사용자 계정으로 로그인하지 않았다. 검증 스크립트는 `.vercel/manual-qa/check-browser.cjs`에 준비했으며 실제 게시 API 호출은 차단하도록 구성했다.
