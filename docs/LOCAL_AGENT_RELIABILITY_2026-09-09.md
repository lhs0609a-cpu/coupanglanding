# 로컬 에이전트 점검·수정 기록

## 적용 상태

- 로컬 PC: **0.6.4 설치 완료**. `/health` 버전, 메가로드 로그인, 렌더러 `hasApi: true`, 탭 5개 확인. 마지막 글 품질 보정 파일 3개도 생성 작업이 없음을 확인한 뒤 설치 runtime에 적용하고 해시 일치를 확인했다. 생성은 별도 프로세스를 시작하므로 다음 생성부터 적용된다.
- 패키지: 최초 0.6.4 NSIS 생성 및 main/runtime 69개 해시 비교는 통과했다. 이후 글 품질 보정이 들어간 최종 설치 파일 재패키징은 지연 중이다. 기존 `worker/desktop/dist/MegaloadDesktop-Setup-0.6.4.exe`를 최종 보정본으로 취급하면 안 된다.
- 서버: 소싱 queue/detail/export API 수정은 저장소에 준비됨. **운영 서버 배포는 아직 하지 않음**.
- 네이버: 설치 후 네이버 로그인 화면이 보안문자를 요구함. 사람 확인 전에는 실수집 성공 여부를 판정할 수 없음.

419의 네이버 내부 판정 기준은 확인하지 못했다. 코드에서 대응 가능한 실패 전파, 요청 중단, 시간 제한, 상태 표시를 수정했다.

## 수정한 동작

### 소싱과 결과 저장

- 셀러의 작업 선점은 허용하면서 저장은 관리자에게만 허용하던 권한 불일치 수정. 셀러는 본인 요청이며 처리 중인 상품만 업데이트할 수 있다.
- 큐 선점을 조건부 UPDATE로 변경. 동시에 여러 PC가 조회해도 실제 선점된 행만 반환한다.
- 실패 시 URL에서 상품번호를 복원해 서버에 보낸다. `blocked`, `retryable`, `apiStatus`도 보존한다.
- 차단·로그인·캡차·영구 HTTP 오류를 구분한다. 404/410 및 차단을 같은 상품에 6회 반복하지 않는다.
- 페이지 이동의 모든 재시도가 실제 탭을 얻은 다음 공유 예산을 받는다. 이전 상품 페이지를 새 상품의 결과로 저장하지 않는다.
- 상품 시간 제한에 게이트 대기·페이지 추출을 포함한다. 시간 초과 탭을 폐기해 늦은 응답이 다음 작업에 섞이지 않게 한다.
- 부가정보 API가 차단하면 뒤의 리뷰 API를 추가로 호출하지 않는다.
- 차단 중 다른 탭의 성공이 백오프를 초기화하거나 일반 실패가 차단 레벨을 낮추지 못하게 한다.
- 수동 배치는 접근 제한·인증 요구 시 남은 건수를 알리고 멈춘다. 큐는 차단 중 새 작업을 선점하지 않는다.
- 후기 자료를 저장 API → 내보내기 → 로컬 상품 파일까지 전달한다.

### 탭과 이미지

- 준비 중인 탭은 작업에 배정하지 않는다. 탭 개수 조정은 한 번에 하나만 실행한다.
- 탭 대기를 취소할 수 있고, 중지된 풀은 대기자를 남기지 않는다. 목록용 0번 탭을 축소 과정에서 잃지 않게 한다.
- URL 변경 없이 하위 메뉴가 실제로 보이면 메뉴 이동을 성공으로 판정한다. 단순 클릭 무반응을 성공으로 보지는 않는다.
- 이미지 요청은 본문 수신까지 30초 제한, 원본 24MB 및 디코딩 픽셀 상한을 적용한다.
- 파일 확장자 대신 실제 디코딩으로 이미지를 검증한다. HTML 오류 본문을 JPEG 파일로 저장하지 않는다.
- 대표·리뷰 이미지는 긴 변을 제한하고, 세로 상세 이미지는 가로 폭을 유지한다. EXIF 방향과 흰 배경을 처리한다.
- 중복 이미지 주소를 제거하고 다운로드 동시성의 슬롯 인계를 수정한다.
- 다운로드는 `.ingest` 안에서 준비하고 완료된 폴더만 `product_*`로 옮긴다. 재수집 전 폴더는 `.previous`로 보존한다.
- 대표이미지 저장 0건은 완료로 처리하지 않는다.

### 글 생성과 진행 표시

- 텍스트·비전·모델 상태 조회에 시간 제한을 추가했다. 취소·시간 초과를 네트워크 재시도로 증폭하지 않는다.
- 설치된 모델 이름을 정확한 태그로 확인한다. 3B가 있다고 7B 설치가 끝났다고 판단하지 않는다.
- 노출명 재작성 후 이전 응답의 속성어·키워드를 재사용하지 않는다. 최종 결과를 다시 검증한다.
- 선택 옵션의 규격을 상품 전체의 고정 규격으로 끼워 넣지 못하게 검사한다.
- 고정 품목 예시와 허구 사용 후기 예시를 제거하고 프롬프트를 압축했다. 별도 고시로 보존하는 원산지 정보를 카피 금지어와 충돌하는 글감으로 제공하지 않는다.
- 허구 체험담·품질 보장 단정·불릿 과다를 검수한다. 실패한 문장을 통과로 표시하지 않는다.
- 상세 설명은 JSON 스키마로 문단 2개·요점 3개를 요청한다. 생성한 검색어는 사실 근거에서 제외하고 검색어 채우기용 추천 문장도 덧붙이지 않는다.
- 원본에 없는 식감·품질 유지·안전 배송 등의 표현을 검수한다. 재시도 후에도 실패하면 생성문을 버리고 원본 옵션·판매자 안내로 만든 초안을 제공하며 검수 필요 상태를 유지한다.
- 비전 일반 오류가 연속되면 해당 배치의 비전 호출을 중단하고 기존 이미지 판정 방식으로 넘긴다.
- 생성 0건은 실패 코드와 `.failure.json`을 남기며 기존 생성 파일을 보존한다. 부분 실패·미처리도 집계한다.
- UTF-8 및 진행 마커가 출력 청크 사이에서 나뉘어도 복원한다. 출력 스트림 종료 후 최종 상태를 알린다.
- 웹 타입 검사에서 별도 데스크톱 배포물 디렉터리를 제외했다. 공유 워커 변경과 회귀 테스트를 데스크톱 CI 검증에 연결했다.

## 검증

- 신규 회귀 테스트 **33개 통과**: 네이버 API 권한·선점 경쟁, 차단 전파, 타임아웃, 탭 취소, 이미지 검증·보존, 출력 청크 복원, 생성 0건 CLI 종료와 기존 파일 보존, 구조화 출력·근거 검수·실패 시 원문 초안.
- 저장소 전체 TypeScript `--noEmit` 통과.
- 기존 도우미 발견 규약, 대표이미지 정책, 상품명 복원, 속성어 조립 검사 통과.
- 0.6.4 릴리스 노트 검사, runtime 동기화 검사 및 Windows NSIS 패키징 통과.
- 설치 프로그램 종료 코드 0, 설치 버전 0.6.4, 실행 중 버전 0.6.4 및 렌더러 로딩 확인.

실제 참외 상품의 로컬 모델 샘플도 생성했다. 중간 수정본은 18.1초에 검수를 통과했으나 직접 읽었을 때 근거 없는 효과 표현이 있어 검수기를 강화했다. 최종본은 **51.1초, 본문 시도 3회** 후 원문 기반 초안으로 대체됐다. 노출명은 원본으로 복구됐고 허구 효과 표현은 최종 본문에 남지 않았다. 이 결과는 광고 문체의 품질 통과가 아니며 검수 필요 상태가 맞다. `worker/tests/live-quality-result.json`에 실물 결과를 기록했다. 초기 393.2초와는 모델 로딩·메모리 상태가 달라 동일 조건 속도 비교로 사용할 수 없다.

웹 운영 빌드는 제한 밖에서 재시도해도 Google Fonts 세 종류의 다운로드가 실패했다. TypeScript와 API 회귀 테스트는 통과했지만 전체 웹 빌드 통과는 확인하지 못했다. 기존 undici 선택 의존성 및 넓은 파일 탐색 패턴 경고도 출력됐다.

## 남은 확인

1. 네이버가 요구한 보안문자 완료 후 목록·상세 수집을 소량 재검증한다.
2. 운영 서버에 queue/detail/export 변경을 반영한 뒤 셀러 PC의 결과 저장을 실제 계정으로 확인한다.
3. 글 품질은 원문 기반 초안까지 확인했다. 현재 로컬 모델은 이 상품의 광고 문체 검수를 통과하지 못했다. 여러 카테고리의 실물 품질과 전체 배치 처리 속도는 추가 검증 대상이다.
4. 기존 실행의 85건 실패·246건 미처리를 자동으로 성공 처리하거나 운영 데이터를 임의 수정하지 않았다. 인증과 서버 적용을 확인한 뒤 재처리할 대상이다.

광고 집행·상품 실제 등록·가격 변경은 이번 검증에서 실행하지 않았다.
